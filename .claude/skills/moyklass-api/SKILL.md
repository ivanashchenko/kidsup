# МойКласс API — обязательные правила (кровью написано)

## ГЛАВНОЕ: POST /v1/company/users/{id} — это ПОЛНАЯ ЗАМЕНА
Любое поле, которого нет в теле, СТИРАЕТСЯ: телефон, email, атрибуты
(родитель, дата рождения, тип клиента, Tallanto-история).
**Инцидент 14.08.2026:** массовая смена статусов голым POST затёрла 1844
карточки. Восстанавливали из резервной копии.

Правила:
- Обновление клиента → ТОЛЬКО `MoyKlassClient.safe_update_user()` (GET → merge → POST).
- Статус → `POST /users/{id}/status` {statusId, statusChangeReasonId}.
  Отказ (125957) и набор (125951) БЕЗ причины → 400. Рабочая причина: 313608.
  Недозвон (345768) и «думает» (146950) проходят без причины.
- Теги → `POST /users/{id}/tags` телом `{"tags": [117908]}` — ТОЛЬКО id, не имена.
  `{"tags":["Промо: Маша"]}` и `{"tagIds":[...]}` → 400. Список заменяет прежние:
  сначала прочитай текущие и добавь новый к ним, иначе старые слетят.
- Создание клиента: `POST /v1/company/users` `{"name":..., "phone":"79261234567"}` —
  телефон БЕЗ плюса. С `+7…` и с `advSourceId` в теле → 400. Источник и теги
  проставляются потом отдельными вызовами. Ответственные — тоже суб-эндпоинтом, не полным POST.
- `createSourceId` в теле апдейта → 400 (readOnly).
- ЛЮБАЯ массовая операция (>20 карточек): СНАЧАЛА свежая копия
  data/kidsup.db (или выгрузка users через API) — потом запуск.

## Задачи
- **GET /v1/company/tasks ИГНОРИРУЕТ параметр `date`** — проверено 21.08.2026:
  `date=2026-08-21`, `date=2020-01-01`, `date="zzz"` и запрос вообще без него
  дают ОДИН И ТОТ ЖЕ набор. Фильтра по дню у эндпоинта нет: бери все задачи
  менеджера через `managerId` + пагинацию и отбирай день по полю `beginDate`
  самой задачи. Используй `taskguard.all_tasks(mk, manager_id)`.
- `totalItems` в ответе отсутствует — размер выборки считай по строкам.
- **Автора и времени закрытия задачи в API НЕТ**: ни `completedAt`, ни
  `completedBy`; `managerIds` — это «на кого назначена», а не «кто закрыл».
  Эндпоинтов истории нет (`/tasks/{id}/history`, `/company/audit` → 404).
  Значит «сколько задач закрыл сотрудник» по API НЕ ВЫЧИСЛЯЕТСЯ — не строй
  на этом оценку работы человека.
- Обновление задачи = полный POST /v1/company/tasks/{id} (тоже full replace).
- beginDate/endDate строго "YYYY-MM-DDTHH:MM:SS+00:00" (UTC = МСК−3);
  "YYYY-MM-DD HH:MM" → RequestValidationError.
- Категории: 44337 🔥срочно · 104575 переписка · 104576 звонок · 104577 дожим · 104578 орг.

## Прочее
- Троттлинг ~3 rps (sleep 0.3с между вызовами), ретраи с паузой на сеть.
- Статусы клиентов: 125951 новый лид · 345768 недозвон · 146950 думает ·
  125952 записался · 125957 отказ · 345759 архив набора · 146328 не писать.
- Join update требует statusId; классы archive через API молча игнорируется.
- users?sort=updatedAt&sortDirection=desc — работает; updatedAt[from] — нет (400).
- Поиск users?phone= может не найти существующий номер — проверяй и по локальной БД.
- Комментарии/теги/абонементы живут отдельно от карточки — full-replace их не трогает.

## Имя карточки — только имя ребёнка
Служебное в имя НЕ пишем. Где чему место: канал общения — теги «💬 Отвечает:
WhatsApp/Telegram/MAX» (117413/117414/117415), скидка — тег 118513, запрет
звонить — тег 118514, возраст — атрибут «дата рождения», разовые заметки —
комментарий. Чистит и сторожит `app/imena.py` (`watch` в автопилоте в 19:00).
Полное обновление карточки может отвергнуть чужой email как дубль — тогда
POST без email проходит, но email СТИРАЕТСЯ: возвращать отдельным вызовом.

## Телефон — только формат 7XXXXXXXXXX (решение владельца 29.08.2026)
Без плюса, без восьмёрки, 11 цифр. В этом виде `users?phone=` ищет предсказуемо.
29.08 база приведена к формату: исправлена 32 карточка (8XXX и номера без кода).
Осталось 85 вне формата — иностранные, заглушки 000…, битые: правятся руками,
список в `/base` → «Телефоны на проверку». Любую новую карточку создавать только
в этом формате: `app.ankety.normalize_phone()` вернёт None, если номер не
российский мобильный — такой в CRM не заводим.

## Справочники, которые всё-таки читаются через API
- `GET /v1/company/userTags` — все теги с id (эндпоинта `/tags` нет, будет 404).
- `GET /v1/company/clientStatuses` — все статусы клиентов.
- `GET /v1/company/userAttributes` — атрибуты вместе с вариантами multiselect
  (в `variants` лежат id направлений для «Тип клиента», attributeId 4).
Создать тег или статус через API нельзя — только руками в интерфейсе.

## safe_update_user и пустые атрибуты
Атрибут типа phone/date с пустой строкой в теле POST даёт 400 (карточка 8030380,
пустой «Телефон 2»). `safe_update_user` такие значения не переотправляет.
