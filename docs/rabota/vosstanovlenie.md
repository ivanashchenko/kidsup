# План восстановления app.kidsup.ru, если пропадёт сервер

Составлен 21.10.2026 по поручению Бориса (угроза дата-центру). В файле нет
ни паролей, ни данных клиентов — только порядок действий.

## Что где лежит

| Что | Где | Что будет, если дата-центр пропадёт |
|---|---|---|
| Код сервера | GitHub, ветка `claude/moyklass-crm-export-analysis-gqxs6k` | не пострадает |
| База сервера `data/kidsup.db` (пульт, звонки, переписка, комментарии, кадры, настройки, зеркало МойКласса) | сервер Рег.облака | пропадёт — нужна копия |
| Клиенты, записи, оплаты, занятия | МойКласс (их серверы) | не зависит от нашего дата-центра |
| Ключи доступа (МойКласс, Wazzup, Манго, Hooppy и др.) | таблица `settings` в базе | пропадут вместе с базой, если нет копии |

## Резервные копии

- **Полная копия базы:** `GET /api/backup/db` (только владелец) — файл
  `kidsup_db_ГГГГ-ММ-ДД_ЧЧММ.db.gz`. Снимается штатным `sqlite backup`,
  сервер при этом работает.
- **Данные МойКласса отдельно:** `GET /export/raw/<таблица>.json` —
  users, joins, payments, invoices, classes, courses, filials, managers,
  subscriptions, user_subscriptions, lessons, lesson_records, rooms.
- **Каждую ночь** рутина снимает полную копию и отправляет файл Борису;
  Борис хранит копии у себя (Google Диск / компьютер), вне дата-центра.
- **Снимки сервера Рег.облака** — включаются в панели Рег.облака владельцем
  (Облачные серверы → сервер → Резервное копирование), лучше в другом регионе.

Копии содержат ключи и персональные данные: только у владельца, не в git,
не в чатах.

## Ключи, которые владелец хранит у себя (в менеджере паролей)

Значения есть в последней копии базы (таблица `settings`); названия:
`moyklass_api_key`, `mk_web_login` / `mk_web_password`, `wazzup_key`,
`mango_key`, `hooppy_token`, `roistat_key`, `tilda_secret`, `lead_hook_key`,
`tbank_token`, `komtet_*`, `yandex_*` (Директ, Метрика, вебмастер),
`vk_ads_*`, `ivideon_*`, `cam_password`, `pochta_password`, `tg_webhook_secret`,
`anthropic_api_key` / `anthropic_proxy_secret`, `owner_password`, `pedagog_key`.
Плюс вне базы: пароль админ-входа на сервер (`APP_PASSWORD`), доступ к панели
Рег.облака, к DNS домена kidsup.ru, к GitHub.

## Восстановление на новом сервере (2–4 часа)

1. Взять VPS у другого провайдера или в другом регионе (Ubuntu, 2 ГБ памяти,
   20 ГБ диска): Selectel, Yandex Cloud, Timeweb — любой.
2. Поставить Python 3.11, склонировать репозиторий с GitHub, `pip install -r
   requirements.txt`.
3. Распаковать последнюю копию: `gunzip kidsup_db_….db.gz` →
   `data/kidsup.db` (каталог задаётся `KIDSUP_DATA_DIR`).
4. Задать `APP_PASSWORD` и прочие переменные окружения, запустить службу
   `kidsup` (systemd, `uvicorn app.main:app --host 127.0.0.1 --port 8000`)
   за nginx/caddy с HTTPS.
5. Переключить DNS `app.kidsup.ru` на новый IP; проверить `/api/health`.
6. Обновить адреса вебхуков, если они указывали на IP: Wazzup, Тильда,
   Roistat, Telegram-бот (`tg_webhook_secret`), Манго.
7. Проверить: синхронизация МойКласса, пульт, звонки, Hooppy.

## Если сервер лежит, а восстановление ещё идёт

Админы работают напрямую в МойКлассе и Wazzup: запись, оплаты, переписка
не останавливаются. Временно недоступны пульт, разбор звонков, камеры и
автоматика — их заменяет ручной список дел в чате «Администраторы».
