# Сверка оплат месяца: МойКласс ↔ Т-Банк ↔ Комтет ↔ тетрадь

Страница владельца `/boris/docs/sverka-oplat` («Сверка оплат ноября: МойКласс ↔ Т-Банк ↔ Комтет ↔ тетрадь»).
Задача Бориса 28.10: «По оплатам ноября делай сверки!! Т-банк (торговый и интернет эквайринг, и поступления
счет), Комтет-касса, фотка по кассе в чате админов!»

Скрипты восстановлены 10.11.2026 (прежние пропали при откате контейнера 07.11). Здесь только код:
выгрузки, снимок и сама страница содержат имена детей и суммы, поэтому живут в рабочей папке, а не в
репозитории (он публичный). Номеров счетов, карт, паролей и токенов в коде нет — номера счетов берутся из
ответа банка во время работы.

## Ежедневная рутина

Из рабочей папки (в ней лежат обёртки `sverka_nov/sverka.py` и `sverka_nov/page.py`, которые запускают код
отсюда и ставят `SVERKA_DIR`):

```
python3 sverka_nov/sverka.py fetch <позавчера> <сегодня>    # свежие данные → sverka_nov/in/, снимок → sverka_nov/snap/
# фото из sverka_nov/foto.json, которых нет в tetrad.json, смотрит человек/агент и переносит страницу тетради
python3 sverka_nov/page.py --post                         # собрать и выложить страницу
```

Без `--post` страница только собирается в `sverka_nov/page_new.html`. Другие ключи `page.py`:
`--month 2026-11`, `--prodazhi-s 2026-10-24` (с какого дня принимаются оплаты месяца; по умолчанию за 8
дней до 1-го), `--out файл`, `--na 2026-11-07T11:08` — собрать «как было на момент» по данным, созданным до
него (для сравнения со старой версией; с `--post` не сочетается).

Догрузить прошлые дни без фото и без повторной копии МойКласса:
`python3 sverka_nov/sverka.py fetch 2026-09-01 2026-10-21 bank,terminal,komtet`
(источники: `mk`, `bank`, `terminal`, `komtet`, `chat`).

## Откуда что берётся (всё — только чтение)

| Источник | Запрос | Логин |
|---|---|---|
| МойКласс (копия базы сервера) | `/export/raw/{payments,user_subscriptions,users,classes,managers}.json`, `/api/sync/status` | админ, `call()` из `api.py` рабочей папки |
| Т-Банк, счета и выписка | `/api/tbank/get?path=/api/v4/bank-accounts`, `…/api/v1/statement` по каждому счёту | владелец |
| Т-Банк, терминалы по операциям | `…/api/v1/tacq/terminals`, `…/api/v1/tacq/operations/terminal/{key}` (сутки за запрос, 1 запрос/с) | владелец |
| Комтет, чеки | `/api/komtet/cheki?since&till` | владелец |
| Чат «Администраторы», фото | `/api/gruppy/soobsheniya?chat=…` + скачивание картинок | админ |
| Выкладка страницы | `POST /api/boris-docs {slug, title, html, note, order:100}` | владелец |

Пароль владельца читается из файла (`SVERKA_OWNER_PW`, по умолчанию `<папка>/../owner/.pw`) и уходит в curl
через stdin (`curl -K -`), а не аргументом — в выводе и в списке процессов его нет.

Снимок `snap/` накопительный: каждый `fetch` докладывает операции (банк — по `operationId`, терминал — по дням,
чеки — по id) и помнит, за какие дни что загружено (`snap/meta.json → coverage`). МойКласс каждый раз
копируется целиком.

## Как сверяется

Оплата месяца — абонемент в группу с началом в этом месяце или абонемент на несколько занятий, купленный с
даты начала продаж и начинающийся не раньше неё; разовые (1 занятие) и праздники не считаются. Сумма — все
списания на абонемент; деньги — приход, внесённый вместе со списанием (±2 минуты), иначе «с баланса»: баланс
ученика проходится по времени, списание берёт сначала из своего прихода, потом из самого старого прихода с
остатком (в долг — гасится следующим приходом). На странице показан приход, из которого взята большая часть
денег, остальные — списком; ✓ только если сошлись все. Абонементы без единого списания перечислены под таблицей.

Каждый приход МойКласса сверяется поштучно, одна банковская операция — одной оплате:

1. безнал → СБП «Терминал Kids UP» той же суммы в пределах 15 минут;
2. карта → операция нашего терминала в тот же день, та же сумма, ближайшая по времени (какой терминал наш —
   по совпадению его операций за день с зачислением на наш счёт; второй терминал в выдаче — клуба Буракова);
3. оставшийся безнал → реестр интернет-эквайринга за день (сумма до комиссии = сумма оплат дня или их часть);
4. СБП, внесённый позже или не тем типом («карта», «нал») — отдельным пунктом «поправить тип»;
5. одна операция терминала = несколько оплат в МК (родитель приложил карту один раз за всех детей) и наоборот;
6. карта, которой нет в списке операций, — остаток дня «зачислено − операции» (у центра есть терминал,
   которого банк по операциям не отдаёт): если сходится до рубля — «второй терминал»;
7. терминал клуба Буракова ±20 минут — деньги на чужом счёте; иначе «на терминале такой операции нет»;
8. наличные → строка прихода в `tetrad.json` за день (или итог прихода дня);
9. маткапитал (перевод на счёт) → поступление ОСФР той же суммы на любой счёт (по схеме центра оно приходит на
   счёт «Клуб Буракова» того же ИП и оттуда переводится на KidsUP);
10. чек → Комтет: `external_id` = id платежа МК, иначе «Уч №ученика» + сумма (до 3 суток), иначе онлайн-чек
    на брата/сестру той же суммы в пределах 3 часов. Касса клуба Буракова (Люберцы) не учитывается.

Лишние деньги в банке (операция терминала или СБП без оплаты в МК) — пункт Лизе «внести».

### Чем правила отличаются от страницы 07.11

Скрипты 07.11 пропали, поэтому правила восстановлены заново и местами точнее. На тот же момент
(`page.py --na 2026-11-07T11:08`) новые правила дают 14 расхождений вместо 34 на странице 07.11 — это не
разобранные пункты, а уточнение сверки:

- одна операция терминала за несколько оплат (п. 5) — 07.11 такие оплаты шли парой «оплаты нет на терминале» +
  «операция без оплаты в МК»: −13 пунктов;
- «нал в МК, а по банку терминал» — один пункт «поправить тип» вместо двух: −1;
- карта сверяется в пределах дня по дате оплаты, а не в окне в полчаса от времени внесения: −2;
- наличные 28.10 и 02.11: страницы тетради за эти дни утеряны при откате 07.11 и заново не перенесены, оплаты стоят
  «…» вместо пунктов «нет в тетради»: −5 (вернутся, когда дни перенесут в `tetrad.json`);
- маткапитал теперь сверяется с поступлением ОСФР (07.11 такие строки были «платёж не найден» или «…»);
- новое за последнюю минуту до 11:08 — одна операция терминала без оплаты: +1.

Сумма «оплачено» на тот же момент больше на 13 665 ₽ — это правки в МойКлассе после 07.11 (новый абонемент,
удалённое списание, пересчитанная цена трёх абонементов), а не правила. Объяснение для владельца лежит заметкой
на странице (`zametki.json` в рабочей папке).

## zametki.json

Необязательная заметка владельцу над таблицей (данные — в рабочей папке, в ней могут быть имена):

```json
[{"s": "2026-11-10", "do": "2026-11-30", "zagolovok": "…", "abzacy": ["…"], "spisok": ["…"]}]
```

Показывается с `s` по `do` включительно.

## tetrad.json

```json
{"2026-11-09": {"foto": ["2026-11-09T19:47:21+03:00"], "ostatok_nachalo": 78301,
                "prihody": [{"summa": 6615, "chto": "АЯ, абонемент"}], "rashody": [{"summa": 155, "chto": "пластилин"}],
                "ostatok_konec": 78146},
 "_skipped_foto": {"2026-11-09T17:07:21+03:00": "снимок экрана сайта, не тетрадь"}}
```

`foto` — время фото из `foto.json`, с которых перенесён день; фото, которые не тетрадь, — в `_skipped_foto`.
`fetch` печатает фото, которых нет ни там, ни там.
